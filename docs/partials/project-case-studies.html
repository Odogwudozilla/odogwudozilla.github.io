Personal Product Watch

Purpose

I’m building a product watcher that checks offers against product requirements and preferred and maximum unit prices.

Approach

TypeScript on Cloudflare Workers and D1, with separate checking and email-delivery workflows.

Status

Personal project · Owner-only live workspace and an open fictional demo. Private repository.

  • TypeScript
  • Cloudflare Workers
  • D1
  • SQLite
  • GitHub Actions

Criteria and fair comparison

A watch describes a product need rather than a single listing URL. The first slice compares detergent prices per wash, so different pack sizes can be assessed against the same limits. Product variants and missing evidence affect whether an offer qualifies.

Checking and alerting

The private application stores watch criteria, supports manual and scheduled checks, and prepares email alerts for qualifying offers. The TypeScript application runs on Cloudflare Workers with D1 storage; GitHub Actions runs the checking workflows.

A public demo with clear boundaries

Visitors can adjust sample limits, compare fictional offers and preview an alert without signing in. The demo does not search retailers, make purchases or send email. The live workspace is limited to the owner.

Registration and administration

HomeWizard Energy Intelligence

Purpose

I’m building an application to collect smart-meter readings, review energy history, and compare load-shifting scenarios.

Approach

Save readings locally, replay failed uploads and show history with data-coverage checks.

Status

Personal project · Private hosted application. Tariff, solar, battery and cost comparisons are in development.

  • Java
  • React
  • SQLite
  • Supabase
  • Local storage, upload retries, and replay
  • Historical imports and data-coverage checks
  • Recorded readings kept separate from estimates

Collection and recovery

The Java collector reads the HomeWizard API and saves readings in SQLite before uploading them. Failed uploads can be replayed, and ingestion prevents duplicate records.

Energy history

The authenticated React and TypeScript interface uses Supabase data. It shows reading history, coverage, and freshness so missing data is visible when reviewing energy use.

Development status

The private hosted application supports historical exploration and load-shifting scenarios. Tariff, solar, battery, and cost comparisons are still being developed.
