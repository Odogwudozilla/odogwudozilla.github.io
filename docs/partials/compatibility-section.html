Safer rollout: Keep the added field optional for consumers; check stricter clients separately.

What makes the other changes break?
  • Rename title to name: the client no longer finds the title it reads.
  • Change id to a number: the client expects a string, so decoding fails.
  • Require priority in the request: the old request omits it, so validation returns 400 before the client can read a task.

These results apply to the client defined above. A stricter client could reject extra fields; other clients may tolerate different changes. Review actual consumers before changing a real API.
